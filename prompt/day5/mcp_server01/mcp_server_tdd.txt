첨부된 `mcp_server.py`를 기준으로 TDD 테스트 파일을 작성하고, 작성한 테스트를 실제로 실행해줘.

목표:

* `mcp_server.py`의 핵심 진입 함수가 의도대로 동작하는지 테스트한다.
* 테스트 파일을 실제로 생성한다.
* 테스트 실행 시 실제 JSONL 로그도 테스트 전용 경로에 저장되도록 한다.
* 테스트 파일 생성 후 반드시 테스트를 실행한다.
* 테스트 실행 결과와 로그 생성 결과를 보고한다.
* 매번 Claude Code가 거의 같은 테스트 파일을 생성하도록 테스트 파일명, 테스트 클래스명, 테스트 함수명, 테스트 순서, 검증 항목을 고정한다.
* 창의적으로 테스트를 추가하지 말고, 아래에 지정한 테스트만 작성한다.
* 기능 코드는 수정하지 않는다.
* 기존 서버 코드, DB, RAG, ChromaDB, requirements는 수정하지 않는다.

3. 테스트 로그 저장 정책
===============

이번 테스트는 실제 로그 파일이 저장되어야 한다.

테스트 전용 로그 경로:

```text
outputs/day5/mcp_server01/test_logs/
```

예상 로그 파일:

```text
outputs/day5/mcp_server01/test_logs/mcp_server01.jsonl
```

요구사항:

* 테스트 실행 전 `MCP_SERVER01_LOG_DIR` 환경변수를 테스트 전용 로그 디렉터리로 설정한다.
* 테스트 실행 중 `mcp_logging.log_event()`가 실제로 실행되어 JSONL 로그가 저장되게 한다.
* 기존 운영 로그 경로 `outputs/day5/mcp_server01/logs/`가 아니라 테스트 전용 경로를 사용한다.
* 테스트 로그 파일은 테스트 시작 시 삭제하고 새로 생성되게 한다.
* 테스트가 끝난 뒤 로그 파일이 존재하는지 확인한다.
* 로그 파일에 최소 1개 이상의 JSONL 라인이 있는지 확인한다.
* 로그 라인에 민감정보가 없어야 한다.

중요:

* 이번 수정에서는 `mcp_logging.log_event`를 무조건 mock 처리하지 않는다.
* 로그 저장 여부를 확인해야 하는 테스트에서는 실제 `log_event`를 사용한다.
* 다만 executor/selector/schema builder처럼 외부 실행 가능성이 있는 함수는 patch한다.
* 테스트가 실제 로그 파일을 만들더라도, 경로는 반드시 테스트 전용 디렉터리여야 한다.
* 운영 로그 경로에는 로그를 저장하지 않는다.

민감정보 검증:

로그 파일 내용에 아래 문자열이 원문으로 있으면 실패 처리한다.

```text
SECRETabc123
Bearer 
internal.example
http://
https://
```

주의:

* “token”, “endpoint” 같은 단어가 key 이름으로만 등장할 수 있다면 값 노출 여부 중심으로 검사한다.
* 단순 문자열 검사로 과도하게 실패할 가능성이 있으면, 최소한 명시된 secret 값과 URL 원문이 없는지 확인한다.

4. 테스트 setUp / tearDown 고정
==========================

테스트 클래스에 `setUp`과 `tearDown`을 작성한다.

`setUp`에서 수행:

1. 프로젝트 루트 기준 테스트 로그 디렉터리 계산
2. `outputs/day5/mcp_server01/test_logs/` 생성
3. 기존 `mcp_server01.jsonl` 테스트 로그 파일 삭제
4. `MCP_SERVER01_LOG_DIR` 환경변수 설정
5. 필요하면 기존 환경변수 값을 보관

`tearDown`에서 수행:

1. 기존 `MCP_SERVER01_LOG_DIR` 값 복원
2. 테스트 로그 파일은 삭제하지 않는다.

   * 이유: 테스트 후 사용자가 로그 내용을 확인할 수 있어야 한다.

예상 코드 구조:

```python
def setUp(self):
    self.project_root = Path(__file__).resolve().parents[2]
    self.test_log_dir = self.project_root / "outputs" / "day5" / "mcp_server01" / "test_logs"
    self.test_log_path = self.test_log_dir / "mcp_server01.jsonl"
    self.test_log_dir.mkdir(parents=True, exist_ok=True)
    if self.test_log_path.exists():
        self.test_log_path.unlink()
    self._old_log_dir = os.environ.get("MCP_SERVER01_LOG_DIR")
    os.environ["MCP_SERVER01_LOG_DIR"] = str(self.test_log_dir)

def tearDown(self):
    if self._old_log_dir is None:
        os.environ.pop("MCP_SERVER01_LOG_DIR", None)
    else:
        os.environ["MCP_SERVER01_LOG_DIR"] = self._old_log_dir
```

필요 import:

```python
import os
import json
from pathlib import Path
```

5. 로그 검증 helper 추가
==================

테스트 클래스 안에 아래 helper를 추가한다.

```python
def _read_test_log_lines(self):
    self.assertTrue(self.test_log_path.exists(), "테스트 로그 파일이 생성되어야 합니다.")
    text = self.test_log_path.read_text(encoding="utf-8").strip()
    self.assertTrue(text, "테스트 로그 파일에 최소 1줄 이상 기록되어야 합니다.")
    return [json.loads(line) for line in text.splitlines() if line.strip()]

def _assert_log_contains_event_type(self, event_type):
    lines = self._read_test_log_lines()
    event_types = [line.get("event_type") for line in lines]
    self.assertIn(event_type, event_types)

def _assert_log_contains_any_event_type(self, event_types):
    lines = self._read_test_log_lines()
    actual_event_types = [line.get("event_type") for line in lines]
    self.assertTrue(
        any(event_type in actual_event_types for event_type in event_types),
        f"로그에 {event_types} 중 하나가 있어야 합니다. actual={actual_event_types}",
    )

def _assert_log_does_not_expose_sensitive_values(self):
    if not self.test_log_path.exists():
        return
    text = self.test_log_path.read_text(encoding="utf-8")
    forbidden_values = [
        "SECRETabc123",
        "Bearer ",
        "internal.example",
        "http://",
        "https://",
    ]
    for value in forbidden_values:
        self.assertNotIn(value, text)
```

주의:

* helper 이름은 위 이름 그대로 사용한다.
* 로그 JSON 파싱이 실패하면 테스트가 실패해도 된다.
* 이는 JSONL 로그 형식 검증에도 도움이 된다.
* `self.test_log_path.exists`가 아니라 반드시 `self.test_log_path.exists()`로 작성한다.

7. 테스트 작성 원칙
============

아래 원칙을 반드시 지켜줘.

1. 테스트 이름과 순서를 고정한다.
2. 아래 지정한 테스트 외에 임의 테스트를 추가하지 않는다.

4. `run_fastmcp_server()`는 실제 블로킹 서버 실행을 하면 안 된다.

8. 단, executor/selector/build schema 등 외부 실행 성격의 함수는 patch한다.
9. 테스트는 deterministic해야 한다.
10. 현재 시간, 랜덤값에 의존하지 않는다.
11. 환경변수 값을 출력하지 않는다.
12. 비밀값, token, password, endpoint를 테스트 출력에 쓰지 않는다.
13. 테스트 주석에 “초보”, “초보자”라는 표현은 쓰지 않는다.

방법:

* 이전 테스트들과 독립적으로 실행될 수도 있으므로, 이 테스트 안에서 작은 로그 이벤트를 하나 발생시킨다.
* 허용되지 않은 Tool 호출 1회로 로그를 생성한다.
* 단, 외부 DB/LLM/FastMCP 서버 실행은 하지 않는다.

호출 예:

```python
with patch.object(mcp_server, "FORBIDDEN_SQL_TOOLS", {"execute_sql"}), \
     patch.object(mcp_server, "ALLOWED_TOOLS", {"get_equipment_status"}), \
     patch.object(mcp_server.tool_executor, "build_single_tool_plan") as mock_build, \
     patch.object(mcp_server.tool_executor, "execute_tool_plan") as mock_execute:
    mcp_server.call_mcp_tool("execute_sql", {"query": "select * from users"})
    mock_build.assert_not_called()
    mock_execute.assert_not_called()
```

검증:

* 테스트 로그 파일을 읽는다.
* 각 줄을 `json.loads()`로 파싱한다.
* 최소 1줄 이상 있는지 확인한다.
* 각 로그 dict에 `event_type` 또는 이에 준하는 event 필드가 있는지 확인한다.
* `_assert_log_does_not_expose_sensitive_values()` 호출

11. mock/patch 작성 규칙
====================

patch 경로는 반드시 `mcp_server` 모듈 객체 기준으로 작성한다.

예:

```python
with patch.object(mcp_server.tool_executor, "execute_tool_plan") as mock_execute:
    ...
```

권장 import:

```python
import os
import json
import unittest
from pathlib import Path
from unittest.mock import patch

from day5.mcp_server01 import mcp_server
```

주의:

* `patch("day5.mcp_server01...")` 문자열 patch보다 `patch.object`를 우선 사용한다.
* patch 범위는 각 테스트 함수 내부로 제한한다.
* 테스트 간 상태 공유 금지.
* 테스트 순서에 의존하지 마.
* 단, 로그 파일은 테스트 전용 디렉터리에 누적될 수 있다.
